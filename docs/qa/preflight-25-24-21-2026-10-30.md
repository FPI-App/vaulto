## 2. Compatibilidad del APK y Nuevas Dependencias

- **Diagnóstico de Módulos Nativos**:
  - Los APKs existentes (`vaulto-development.apk` y `vaulto-preview-1e732c9.apk`) **no contienen** `expo-blur` ni `expo-linear-gradient` (añadidos en PR #31).
  - Si Metro recarga el bundle JavaScript con el rediseño, la app fallará en runtime al instanciar `BlurView` (`TabBar`) o `LinearGradient` (`DashboardScreen`).
  - **Recompilación necesaria**: Probar visualmente el rediseño en Android requiere un nuevo APK con esos módulos, mediante EAS o un toolchain local preparado.
  - **Vía segura para QA vigente (#25, #24, #21)**: El APK y bundle actualmente activos en `emulator-5554` disponen de SQLCipher (`libop-sqlite.so`), PowerSync (`libpowersync.so`) y autenticación operativos contra el backend QA. Se pueden ejecutar los flujos de sincronización, cifrado y backend sin depender del rediseño visual.

## 3. Planes de Prueba Mínimos Diseñados

### Issue #25 — Recuperación de Abonos Rechazados
1. **Flujo de colisión offline**: Cuenta A genera abono offline con sobrepago -> reconecta -> backend rechaza con SQLSTATE 23514 -> interfaz marca revisión requerida.
2. **Cambio de cuenta A -> B -> A**: Usuario solicita anulación (estado `requested` en `vaulto_sync_recovery`) -> cierra sesión -> ingresa a cuenta B (valida aislamiento de base local cifrada) -> regresa a cuenta A -> valida que el estado `requested` persiste y no se corrompe.
3. **Pérdida de respuesta en RPC**: Desconectar red (`adb reverse --remove` o detención controlada de bridge) justo tras despachar `cancelar_lote_abono` -> reintentar -> verificar idempotencia (recibo `cancelled` o `already_cancelled` sin error 500 ni anulación duplicada).
4. **Reconexión y reactivación de subida**: Registrar operación CRUD posterior -> validar vaciado de cola y convergencia de historial.

### Issue #24 — Robustez del Backend y PowerSync
1. **Replay del mismo lote**: Cliente reenvía un lote ya procesado tras perder la confirmación HTTP -> verificar respuesta `already_applied` con el mismo recibo sin duplicar inserciones.
2. **Rechazo de cliente anterior a 0012**: Ejecutar intento de escritura DML directa (INSERT/UPDATE/DELETE en tablas públicas sin usar `aplicar_lote_sync`) -> verificar rechazo inmediato por RLS y revocación de privilegios (error 42501).
3. **Auditoría de reglas PowerSync**: Cotejar las reglas publicadas en PowerSync con `supabase/powersync/sync_rules.yaml`.

### Issue #21 — Outbox Cifrado y Reenvío sin Duplicar
1. **Mutación en cola offline**: Crear movimiento o deuda offline -> verificar presencia en `ps_crud` (outbox local).
2. **Migración y reinicio forzado**: Ejecutar migración cifrada (`sqlcipher_export`) -> force-stop del proceso -> reabrir app con llave en SecureStore.
3. **Reanudación y subida exactamente una vez**: Restaurar red -> comprobar que la transacción pendiente se envía una sola vez y converge en PostgreSQL sin duplicados.
